# 安全防破解验收清单

用于《软件工程安全防破解》的实施与报告。只在用户授权的应用、测试账号与隔离环境中执行。每项记录：平台/版本、前置条件、步骤、预期、实际结果、证据位置；无法执行则明确“未验证”，不默认通过。

## 1. 审计与授权边界

- [ ] 已确认项目根目录、适用项目说明、已有改动和服务端权限。
- [ ] 已定位客户端及服务端心跳代码、鉴权中间件、超时策略、令牌刷新及日志。
- [ ] 已区分协议级Ping/Pong与业务授权心跳；找不到服务端实现不能写“心跳已完整存在”。
- [ ] 已记录目标平台、架构、最低版本、离线需求、合法插件/企业安全组件以及发布渠道。
- [ ] 测试不涉及真实用户秘密、他人进程或未经授权的生产修改。

## 2. 服务端安全边界

- [ ] 未登录、错误账号、错误角色、跨租户/跨资源访问、过期/撤销凭证均被服务端拒绝。
- [ ] 将客户端isLicensed/isAdmin或UI状态改为成功，不能绕过敏感接口鉴权。
- [ ] 心跳租约失效后，即便客户端仍显示在线，服务端也拒绝受在线策略保护的操作。
- [ ] 服务端保留必须的业务秘密；客户端中没有共享主密钥、签名私钥或服务端凭据。

## 3. 传输与密钥

- [ ] HTTP/ws明文入口不能承载敏感请求；重定向与错误处理不泄露凭据，不降级绕过TLS。
- [ ] 错误主机名、过期/不可信证书、被替换证书按预期失败，合法证书轮换正常。
- [ ] URL、访问日志、崩溃日志、浏览器控制台和遥测不含令牌/敏感明文。
- [ ] 若使用额外AEAD：标签/密文/AAD被改写均拒绝，验证nonce唯一性、并发、重启和轮换。
- [ ] 平台安全存储、登出清理、刷新令牌撤销和最小权限符合设计。

## 4. 防重放与新鲜性

- [ ] 合法首次登录与敏感请求成功，且响应绑定当前session_id、request_id、用途和挑战。
- [ ] 重放之前的登录成功响应，不能建立新会话或延长授权租约。
- [ ] 同一会话重复响应、跨账号/跨会话/跨请求响应、未知请求、错误挑战、过期挑战均拒绝。
- [ ] 修改result、过期时间、请求体摘要或认证字段不能通过完整性检查。
- [ ] 服务端对同一挑战的并发消费最多成功一次，多个实例行为一致。
- [ ] 服务端重启/存储故障时不会让旧挑战重新有效，明确可用性与拒绝策略。
- [ ] 幂等重试不重复收费/执行不可逆操作，与nonce重放拒绝策略相容。
- [ ] 时间回拨/漂移不会无限续期；时间戳或随机响应字段未被当作唯一防重放手段。

## 5. 心跳状态机

- [ ] 已鉴权连接周期性发送/响应业务心跳，配置间隔、超时、抖动和失联窗口明确。
- [ ] 原生Ping/Pong及浏览器应用层heartbeat各自受支持，业务状态验证独立存在。
- [ ] 无Pong、无业务响应、断网、半开连接、网络切换、代理断连和服务端重启正确收敛。
- [ ] 失联宽限有上限，客户端不能通过缓存心跳或自报时间永久在线。
- [ ] 指数退避、速率限制、连接/消息大小限制正常；不会产生重复计时器/重连风暴。
- [ ] 登出、会话吊销、令牌轮换、重复连接等不会遗留可用旧租约。
- [ ] 移动后台、浏览器节流和桌面休眠/唤醒有明确策略，不以平台无法保证的持续运行作为前提。

## 6. 混淆与虚拟化发行产物

- [ ] 已核实工具及LLVM版本、平台兼容、许可证、构建参数和CI来源。
- [ ] 源码/LLVM IR、IL/DEX、JS/Wasm、原生机器码处理路线区分清楚。
- [ ] 能在真实产物中验证自定义指令表示/VM分发运行时，不以普通混淆、去符号或压缩冒充虚拟化。
- [ ] 应用自有模块总量、已保护范围和排除项有清单；宣称全程序时有完整覆盖依据。
- [ ] 不支持的第三方/FFI/JIT区域明确列出并经范围确认，没有意外未保护副本。
- [ ] 原版与保护版通过功能、ABI、异常、并发、线程、启动、更新和崩溃回溯测试。
- [ ] 已测量启动时延、关键操作延迟、CPU、内存、包体和电量（适用时），相对基线变化可接受。
- [ ] 私有调试符号正确保留但不随发行包公开；最终签名、公证/商店校验及升级流程未受破坏。

## 7. 运行时完整性与平台兼容

- [ ] 正常未修改的真实Release包在目标版本/架构启动，合法系统库、输入法、辅助功能与获准插件不会被误杀。
- [ ] 发布策略中的调试拒绝仅作用于自有进程，Debug/测试构建仍可维护；发行包无易用绕过开关。
- [ ] Windows未授权DLL按验证过的签名/路径/版本策略被拒绝，合法安全组件兼容；不以文件名作唯一依据。
- [ ] 篡改发行文件/受测代码段触发预期拒绝；应用安全退出或停止受保护功能，不损坏用户文件。
- [ ] 签名清单绑定版本/架构/模块身份，错误签名、旧基线、未知构建和网络中间人替换均拒绝。
- [ ] ASLR、重定位、导入修复、合法动态代码及虚拟化运行时变化不造成原始磁盘/内存哈希误报。
- [ ] 更新后新代码使用新基线，旧版本兼容、撤销及回滚策略明晰，未发生自引用哈希循环。
- [ ] 已说明代码段外Hook、手工映射、检测器自身被修改和TOCTOU等不能完全覆盖的情况。
- [ ] macOS/iOS/Android/Linux仅承诺各平台实际支持能力；浏览器未承诺禁止开发者工具或可靠本地秘密保密。

## 8. 补充证据、协议与发布检查

- [ ] 结论区分源码、静态产物、运行观察、推断和未知；包含摘要/构建ID及定位，没有用空结果或截断证明安全。
- [ ] 根据references/protocol-tests.md覆盖跨实例并发消费、消费后故障、存储满/失联、幂等重试、AEAD方向密钥与重启nonce唯一性。
- [ ] 身份切换和迟到回调不能更新新会话；Ping存活而租约失效时敏感操作仍拒绝。
- [ ] Electron IPC或浏览器Origin/CSRF边界按实际技术栈验证；不适用项附理由。
- [ ] 依赖/构建版本与签名来源可追溯；升级包、清单、基线一致；密钥轮换和最低安全版本回滚策略有验证。
- [ ] REA若使用，只调用实际工具；保留Evidence及限制，不擅自执行不可信目标或安装引擎；未用REA不算测试失败。
- [ ] 抓包/日志/报告已经最小化与脱敏，公共仓库不含测试账号、客户数据或原始敏感报告。
