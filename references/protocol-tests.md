# 协议、心跳与负向测试设计

这是测试规范，不是新的密码学协议，也不是已经执行过的测试。先复用项目标准认证/会话库和既有兼容要求；只对测试账号、隔离服务和明确授权的目标执行。禁止用真实客户令牌或生产扣费测试重放。

## 1. 先写清服务端不变量

- 每个敏感接口独立验证主体、会话、租户/资源权限、撤销状态与适用的在线租约，不能只检查WebSocket连接存在。
- 权威时间和到期策略来自服务端；客户端时钟仅用于本地超时提示。分布式存储不可用时对受保护操作拒绝或按批准的有界策略降级，不能默认授权成功。
- 挑战/请求标识绑定协议版本、当前认证主体/会话、用途、请求体摘要及期限；请求和响应方向隔离。挑战唯一性、认证完整性与一次性消费缺一不可。
- 密码学认证应使用标准编码与审核过的库。字段拒绝歧义：重复键、类型混用、非规范编码、未知关键版本及超长输入不得出现不同组件解释不同内容的情况。
- 幂等键不是nonce。对状态变化的操作，授权、挑战消费、幂等记录与业务写入应在事务/可证明一致性机制下配合；重试结果是否可复用需有明确协议，不能让“消费成功但业务丢失”导致重复执行。
- 多实例共用正确的原子防重放状态；TTL、容量、淘汰、持久性和重启恢复都有测试。缓存满或驱逐不能使尚未过期的旧挑战重新有效。
- AEAD nonce与业务nonce分离。按密钥、通信方向和进程生命周期保证AEAD nonce不复用；重启/回滚/计数器回绕前换密钥或使用协议证明安全的分配方式。不要给重放挑战的随机化逻辑顺手复用加密nonce。

## 2. 心跳状态机契约

| 当前状态 | 事件 | 预期动作 |
| --- | --- | --- |
| 未鉴权/连接中 | socket建立或Ping/Pong | 只证明链路；不能开放敏感操作 |
| 已鉴权/在线 | 正确且新鲜的挑战响应 | 按服务端策略更新有界租约 |
| 在线 | 缺失/超时、休眠、断网 | 进入有上限的宽限或立即受限；不得无限续租 |
| 宽限/受限 | 恢复网络 | 重新核验会话与新挑战；不能重放缓存成功结果 |
| 任意 | 登出、撤销、主体切换 | 使旧请求、连接、定时器和租约失效 |
| 任意 | 无效签名/标签、跨会话响应 | 拒绝并记录脱敏原因；不延长有效期 |

具体间隔、租约长度、宽限、退避与抖动不是通用固定值：从业务离线要求、代理超时、移动后台限制和容量预算推导，并记录选择依据。租约到期后本地UI可提示，但真正的敏感访问必须被服务端拒绝。

## 3. 最小测试矩阵

每例记录前置状态、输入类别、客户端状态、服务端响应/状态、业务副作用次数、脱敏日志、实际结果。时间和并发测试优先使用可控时钟/同步屏障，不能仅sleep后看一次UI。

| ID | 场景 | 必须检查的结果 |
| --- | --- | --- |
| AUTH-01 | 未登录/过期/撤销/错误角色访问敏感接口 | 服务端拒绝；零未授权副作用 |
| AUTH-02 | 主体A访问B的租户/对象；仅改客户端登录布尔值 | 越权失败；不能只验证UI禁用 |
| REPLAY-01 | 保存一次合法登录响应，在新会话或新请求中回放 | 客户端关联校验拒绝；服务端接口仍独立鉴权 |
| REPLAY-02 | 同一挑战同时发往两个服务实例 | 按协议最多一次状态变更；其他重复拒绝或得到已授权幂等结果 |
| REPLAY-03 | 改用途、请求体、主体、到期、result、key_id | 认证或关联验证失败，零副作用 |
| REPLAY-04 | 原响应丢失后重试；消费后服务重启；防重放存储失联/满 | 无重复扣费/执行；明确可恢复性与拒绝策略 |
| CRYPTO-01 | 标签/密文/AAD单字节篡改、错误证书/主机名 | 拒绝，不自动降级明文或跳过验签 |
| CRYPTO-02 | 并发、进程重启、密钥轮换、计数器回绕边界 | 同密钥下加密nonce不复用；过渡行为明确 |
| HB-01 | 原生Ping正常但业务授权过期 | 链路可活着，敏感操作必须失败 |
| HB-02 | 无Pong/无业务响应、半开连接、网络切换、代理空闲断连 | 有界转入受限；退避重连；仅一个有效心跳循环 |
| HB-03 | 多次休眠/唤醒、浏览器后台节流、移动后台挂起 | 不无限宽限；恢复后新鲜认证，不误承诺持续保活 |
| HB-04 | 连接建立后撤销会话、主体切换、旧定时回调迟到 | 旧连接/回调不能更新新会话或延长旧租约 |
| INPUT-01 | 重复键、超长消息、类型/编码歧义、未知关键协议版本 | 一致且有界拒绝，无解析分歧与资源耗尽 |
| UPDATE-01 | 旧客户端与新服务端/新客户端与旧服务端 | 明确协商或拒绝，不出现旧版本绕过路径 |

## 4. 落地顺序和结果解释

1. 先读项目现有测试入口、fixture和隔离约定，记录未修改时的基线失败。
2. 为发现的问题先补能复现的负向用例，再做最小修复；保留正常路径和兼容测试。
3. 使用真实服务端中间件与持久化路径验证安全边界。纯mock适合单元验证，但不能替代跨实例原子性和服务器拒绝证据。
4. 比较客户端输出、服务端状态与业务副作用；日志不含令牌、挑战密钥或敏感业务明文。
5. 状态分为通过、失败、阻塞、不适用（给理由）。没有执行不能填写“通过”，未授权访问生产不能记为“线上已验证”。
